# Metal native State persistence

Native Save now writes DS4MST02, version 2. This is an intentional format break:
Load rejects DS4MST01/version 1. Older payloads lack model provenance and must
be regenerated by replaying their token history on the admitted model. There
is no shape-only migration or identity override.

The header preserves context, frontier, field counts and per-layer cache counts,
then stores two 32-byte identities: SHA-256 of the complete model file and a
deterministic digest of tensor names, quantization types and dimensions. Full
content binds tokenizer and metadata as well as weights. Independent request
States share the immutable owner's lazy identity cache; hashing occurs once
on first native Save/Load, not on each evaluation.

Load validates both identities before synchronizing or copying any mutable
buffer. Missing identity, a different model or quantization, invalid geometry,
truncation and trailing bytes fail without changing the State or cache key.
Snapshot ownership and explicit same-queue synchronization remain separate
checks. This native format is not upstream KVC.

Bounded host fixtures cover round-trip, foreign ownership, identity mutations,
same-shape different model and failed-load preservation. The registered-model
TestMetalIndependentStateGate is opt-in and remains physically unqualified
until its device and source-mutant receipts are recorded.
