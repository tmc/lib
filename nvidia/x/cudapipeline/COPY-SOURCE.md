# Scheduled copy source

PipelineSchedule.CopySources validates a bounded stage protocol and emits two
standalone CUDA C++ reference kernels with the same copy extent. The synchronous
kernel uses ordinary shared-memory staging. The asynchronous kernel uses SM80+
16-byte cp.async copies, per-thread commit/wait, and CTA publication/release
barriers. These are not TMA or mbarrier instruction lowerings.

Launch exactly one 64-thread CTA. The first warp produces and the second consumes.
Source and destination must be disjoint, 16-byte aligned, and large enough for
the complete scheduled extent. Stage payloads must be positive multiples of 16,
with at most eight stages, 48 KiB shared memory, and 64 MiB total copied bytes.
The schedule must drain every stage and balance every transaction.

The host oracle executes the synchronous emitted body using 64 C++ threads and
real host barriers, checking independently generated bytes and output guards.
CUDA_PIPELINE_COPY_NATIVE=1, a validated inherited cudalock host lease, and an
explicit canonical CUDA_PIPELINE_COPY_UUID enable a CUDA executable that runs
both kernels and checks CUDA errors, independent bytes, and guards. The fixture
rechecks the same owner record before launch and resolves that exact UUID using
the driver before selecting a device or allocating. The host lease has no device
scope; the UUID is an explicit requested identity, not additional authorization.
GPU_LOCK_HELD carries the owner PID; the Boolean value 1 is not a lease. Set NVCC
to an admitted explicit compiler. Compilation alone does not prove device results
or a performance advantage.

Reference: [PTX cp.async](https://docs.nvidia.com/cuda/parallel-thread-execution/#data-movement-and-conversion-instructions-cp-async).
