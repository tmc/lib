# Audit: github.com/tmc/lib/nvidia/nvml vs NVIDIA/go-nvml

> **Re-audit 2026-08-31 (post-regeneration):** all four bug classes below are
> fixed in the regenerated bindings (files dated 2026-08-31 00:47). Verified:
> 376/376 function pointers registered (zero unregistered; deprecated wrappers
> now callable); output-only versioned structs stamp `Version` internally
> (`MarginTemperature`, `NvLinkInfo`, `PciInfoExt`, `Pdi`, `RepairStatus`,
> `DeviceAddressingMode`, `DeviceCapabilities`, `VgpuRuntimeState`) while
> input-bearing ones (`Temperature`, `ClockOffset`, `CoolerInfo`) now take a
> caller-supplied pointer — resolving both the stamping and dropped-input
> problems; `nvmlDeviceGetBBXTimeData_v1` and `nvmlSystemGetCPER_v1` are bound;
> `ErrDeprecated (26)` added and the `ErrFreqNotSupported` comment corrected.
> Base-symbol coverage is now 377/377 — identical to the official library's
> bound set. `go test` (790+ layout assertions) and `go vet` pass; no duplicate
> registrations. Of the recommendations, only #5 (versioned-symbol fallback for
> older drivers) remains open, by design. The findings below are retained for
> historical reference.
>
> **Follow-up finding (same day, post-regeneration):** three wrappers
> misclassified a C array out-parameter as a scalar return
> (`deviceGetGpuInstances`, `gpuInstanceGetComputeInstances`,
> `deviceGetProcessUtilization`), passing `&out` — one stack struct — where
> NVML writes up to `*count` elements: a stack-corruption hazard. Fixed in
> gen-nvidia (params reclassified as caller-supplied arrays in NVMLConfig),
> regenerated, and re-verified: signatures now take `*T` array pointers with
> correct C argument order; full regression sweep (registration parity,
> version stamping, 377-symbol coverage, `go test`/`go vet`) clean.
>
> **Ergonomics upgrade (lib commit 93d53cd, from codegen c486c90):** the ~21
> count-query enumeration APIs now return slices with optional caller-buffer
> reuse (`procs, err := dev.GetComputeRunningProcesses(buf)`); the
> `ErrInsufficientSize` grow-with-headroom retry loop lives in the generated
> wrapper. Special shapes: `GetRetiredPages` returns paired
> `(addresses, timestamps []uint64)`; `GetSamples`/`GetVgpuUtilization` return
> the `ValueType` after the slice. MIG instance listing (`GetGpuInstances`,
> `GetComputeInstances`) and `SystemGetTopologyGpuSet` stay in raw
> caller-array form (their C convention truncates rather than reporting
> required size). `GetMemoryInfo` upgraded to `nvmlDeviceGetMemoryInfo_v2`
> returning stamped `MemoryV2`. This removes go-nvml's main ergonomic
> advantage while keeping zero-alloc polling, which go-nvml cannot do. An
> intermediate staging (codegen b4a2c4f, generated by internal/ffigen) was
> rejected in verification: it silently reverted four fixed defect classes —
> the scalar-return corruption shape, version stamping, BBX/CPER, and
> `ErrDeprecated` — because those fixes lived only in the contrib/cuda
> generator lineage; c486c90 ported them into ffigen. Final tree verified
> byte-identical to the approved staging; all 13 packages in the nvidia
> module build, vet, and test clean.

Local: `github.com/tmc/lib/nvidia/nvml` (generated by gen-nvidia, files dated 2026-07-31)
Official: `github.com/NVIDIA/go-nvml` @ `616db77` (2026-08-13), NVML API v13 header

## Summary

The local binding is a clean, purego-based 1:1 mapping with near-complete
coverage (352 of 377 current NVML entry points), struct layouts that match the
official bindings exactly, and a more idiomatic Go surface than NVIDIA's. It
has two defect classes that make ~33 exported methods always fail at runtime:
23 deprecated wrappers whose function pointers are never registered, and ~10
versioned-struct wrappers that pass zero-valued structs without stamping the
required `Version` field. Everything else is a difference in design philosophy,
not correctness.

## Bugs

### 1. 23 exported wrappers are never registered (always return *SymbolError)

Every wrapper marked `Deprecated:` has its `fn*` pointer declared in
`funcs.gen.go` but no matching `register()` call in `registerFuncs`
(`init.gen.go:236`). The counts match exactly: 374 pointers declared, 352
registered, 23 Deprecated-tagged (`fnErrorString` accounts for the off-by-one).

Calling one of these (e.g. `Device.GetTemperature`, `device.gen.go:1795`)
returns a `SymbolError` claiming the driver lacks the symbol — misleading,
since every real driver exports `nvmlDeviceGetTemperature`; the binding never
looked it up. Either the generator should register these or it should not emit
the wrappers; exporting methods that can never succeed is the worst of both.

Affected (base C symbols):

- nvmlDeviceGetApplicationsClock
- nvmlDeviceGetCurrentClocksThrottleReasons
- nvmlDeviceGetDefaultApplicationsClock
- nvmlDeviceGetDetailedEccErrors
- nvmlDeviceGetGpuFabricInfo
- nvmlDeviceGetHandleBySerial
- nvmlDeviceGetNvLinkUtilizationControl
- nvmlDeviceGetNvLinkUtilizationCounter
- nvmlDeviceGetPowerManagementMode
- nvmlDeviceGetPowerState
- nvmlDeviceGetSupportedClocksThrottleReasons
- nvmlDeviceGetTemperature
- nvmlDeviceGetViolationStatus

### 2. Versioned-struct wrappers pass unstamped zero structs

Where a wrapper hides the output struct, it does `var out T` and calls the C
function without setting `out.Version` (e.g. `deviceGetTemperatureV`,
`funcs.gen.go:3760`). NVML rejects these with
`ErrArgumentVersionMismatch`. The correct stamps already exist in
`versions.gen.go` (e.g. `TemperatureV1Version = 0x100000c`) but go unused.
The official bindings stamp versions inside every such wrapper.

Affected wrappers (struct type in parens; all verified to carry a `Version`
field):

- `Device.GetTemperatureV` (Temperature) — also drops the **input** field `SensorType`
- `Device.GetMarginTemperature` (MarginTemperature)
- `Device.GetAddressingMode` (DeviceAddressingMode)
- `Device.GetClockOffsets` (ClockOffset) — also drops inputs `Type`, `Pstate`
- `Device.GetCoolerInfo` (CoolerInfo) — also drops input `Index`
- `Device.GetNvLinkInfo` (NvLinkInfo)
- `Device.GetPciInfoExt` (PciInfoExt)
- `Device.GetPdi` (Pdi)
- `Device.GetRepairStatus` (RepairStatus)
- `VgpuInstance.GetRuntimeStateSize` (VgpuRuntimeState)

The pointer-accepting `...V` wrappers (`GetGpuFabricInfoV`, `GetC2cModeInfoV`,
`GetGpuInstanceProfileInfoV`, ...) are fine — the caller supplies and stamps
the struct there.

### 3. Two current functions missing entirely

`nvmlDeviceGetBBXTimeData_v1` and `nvmlSystemGetCPER_v1` have no wrapper and no
registration. These are the only two declarations in nvml.h whose *base* name
carries a `_v1` suffix (no unversioned alias declaration), so the generator
likely fails to pick up `_vN`-only declarations. Both are bound by the official
library.

### 4. Minor: Result gaps

- `Result` is missing code 26, `NVML_ERROR_DEPRECATED` (`result.gen.go` jumps
  25 → 27).
- `ErrFreqNotSupported` (24) has a copy-paste comment from code 23 ("Ran out of
  critical resources, other than memory"); should be "requested frequency is
  not supported".

### 5. Documentation claim

`doc.gen.go` states the package "maps every function from nvml.h". With 23
half-mapped and 2 absent, this is not currently true.

## Design deltas vs official (trade-offs, not bugs)

- **No versioned-symbol fallback.** Local pins each function to one symbol
  version (39 pins, e.g. `nvmlDeviceGetComputeRunningProcesses_v3`,
  `nvmlDeviceGetGridLicensableFeatures_v4`) and leaves it unbound if absent.
  Official `updateVersionedSymbols` (`lib.go:201`) binds the unversioned symbol
  and upgrades to `_v2`/`_v3` when present, with struct conversion
  (`ProcessInfo_v1Slice.ToProcessInfoSlice`), degrading gracefully on older
  drivers. On a pre-R510 driver, local `GetComputeRunningProcesses` simply
  fails. `Has()`/`Has*()` probes make this discoverable but not transparent.
- **No INSUFFICIENT_SIZE retry helpers.** Array-returning calls expose the raw
  C count/pointer dance (`GetComputeRunningProcesses(infoCount *uint32, infos
  *ProcessInfo)`); official wrappers loop-and-grow and return `[]ProcessInfo`.
  Consistent with the package's low-level charter, but every caller
  reimplements the loop.
- **No interface/mock layer.** Official ships `nvml.Interface` and interface
  device handles plus a generated `mock` package; local `Device uintptr` has no
  test seam.
- **Lifecycle.** Official refcounts `Init`/`Shutdown` and dlcloses at zero;
  local lazily dlopens on first call, never refcounts, and documents `Close()`
  as test-teardown-only (`init.gen.go:100`). Reasonable and honestly
  documented.

## Where the local binding is better

- **Cgo-free** (ebitengine/purego): cross-compiles, no C toolchain, carries
  Windows (`nvml.dll`) and darwin library names; official is effectively
  cgo + Linux.
- **Idiomatic errors**: returns `error` (nil on success) with rich
  `nvmlErrorString` messages and a typed `Result` usable with `errors.Is`/`As`;
  official returns a bare `Return` compared against `SUCCESS`.
- **Newer surface than official's ergonomic layer**: SystemEventSet, PRM
  counters, RUSD, PowerMizer, device hostname, repair status, workload power
  profiles are all bound.
- **Layout verification**: `layout_test.go` asserts 790 generator-computed
  sizes/offsets/alignments (passing). Spot-checks of `ProcessInfo`,
  `FieldValue`, `EventData`, `Sample`, and union handling (`[1]uint64` vs
  official `[8]byte` — same size, stricter alignment) match official
  `types_gen.go` exactly.
- **Symbol probes**: `Has("nvmlX")` and per-function `HasX()` let callers probe
  driver capability up front; official has no equivalent.
- **Docs**: godoc-linked per-function comments plus a categorized index in
  `doc.gen.go`.

## Coverage math

- Official nvml.h v13: 412 DECLDIR declarations, 376 unique base names.
- Official Go bindings call 413 symbols (377 base names).
- Local registers 352 symbols (all present in the official set; zero
  local-only).
- Gap: 25 base names = 23 unregistered-deprecated (bug 1) + 2 absent (bug 3).

## Recommended fixes (all in the gen-nvidia generator, not hand-edits)

1. Register the 23 deprecated symbols, or stop emitting their wrappers.
2. Stamp `Version` (and expose input fields such as `SensorType`,
   `ClockOffset.Type`/`Pstate`, `CoolerInfo.Index`) in the zero-struct
   wrappers, using the constants already emitted in `versions.gen.go`.
3. Teach the generator to bind `_vN`-only declarations
   (`nvmlDeviceGetBBXTimeData_v1`, `nvmlSystemGetCPER_v1`).
4. Add `ErrDeprecated (26)` and fix the `ErrFreqNotSupported` comment.
5. Consider optional versioned-symbol fallback (register newest available of
   `_v3`/`_v2`/`_v1`) to match official graceful degradation on older drivers.
