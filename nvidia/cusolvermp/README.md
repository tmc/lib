# cusolvermp

Go bindings for NVIDIA cuSOLVERMp, the distributed dense linear algebra
library. Generated by `codegen/cmd/gen-cusolvermp` from the pinned
`cusolverMp.h` of the 0.9.1 redistributable; the provenance and digests are in
that command's `headers/README.md`.

FFI is purego. There is no cgo in this package.

## Status

Implemented, physically unverified. Nothing here has run against a GPU, a NCCL
communicator or more than one rank. What has been verified is the ABI, against
a CPU-only fixture compiled from the same header: argument order, by-value
widths, out-parameters, the error type, and the loader's behavior when the
library or a symbol is absent. See `TestNativeFixture` in the generator.

Validating it physically needs a multi-rank, multi-GPU job: one process per
GPU, at least two NVIDIA GPUs, a driver for the CUDA 12 build,
`libcusolverMp.so.0` with `libnccl.so.2` and `libcuda.so.1`, and a launcher
that gives every rank the same NCCL unique ID. `physical_test.go` is that
consumer test. It skips with the exact list of what it needs, and once opted in
it fails rather than skips.

## Scope

Bound: handle lifecycle, the NCCL-backed process grid, matrix descriptors, the
grid allocator and buffer registration, `NUMROC`, the workspace queries, the LU
factorize-and-solve pair, and the process-wide logger.

Not bound: the QR family, the least-squares solver, the symmetric and
generalized eigensolvers, the SVD, the polar decomposition and the Newton-Schulz
iteration. They are declared by the header and left out until the common path
has run on real hardware.

`cusolverMpSetMathMode` and `cusolverMpGetMathMode` are declared by the 0.9.1
header but are not exported by the 0.9.1 library. They are bound anyway, so a
build that does export them works and one that does not returns `*SymbolError`.
Use `HasSetMathMode` to tell the two apart.

## Loader

This package opens `libcusolverMp.so.0` itself and shares no loader state with
`cusolver`, `nccl` or `cublasmp`. Loading is lazy: importing the package opens
nothing. `Load` takes an explicit path, `CUSOLVERMP_LIB_PATH` names one,
`CODEGEN_SKIP_BINDINGS` disables loading entirely, and `Has` and the generated
`HasXxx` predicates report which symbols resolved. Every entry point returns a
structured error when the library or its symbol is unavailable. None panics.

It borrows types from `cusolver` (`Result`, `Stream`, `DataType`, `Operation`,
`MathMode`) and from `nccl` (`Comm`), so a caller does not learn a second error
or handle vocabulary. It does not load either library.

## Ownership

Documented in full in the package doc, under five headings. In short:

- **Rank and device mapping.** A handle belongs to one rank, one device and one
  stream for its whole life. It is not portable and not safe for concurrent use.
- **Local layouts.** Matrices are 2D block-cyclic; each rank holds one block.
  `NUMROC` gives the local extents, and the leading dimension has to be at least
  the local row count. A smaller one is a silent memory error.
- **Collective ordering.** Every call taking a `Grid` or `MatrixDescriptor` is
  collective. All ranks must reach it, with matching arguments, in the same
  order. Returning early on a local error leaves the others waiting.
- **Workspace lifetime.** The two `*BufferSize` queries return a device size and
  a host size specific to the arguments they were asked about. The caller owns
  both buffers, keeps them alive until the stream has completed, and does not
  share one between operations in flight.
- **Coordinated cleanup.** Synchronize, then destroy descriptors, grid, handle,
  and only then the communicator and the buffers. Every rank does the same.

`DevicePtr` and `HostPtr` are `uintptr`, never `unsafe.Pointer`: nothing in this
package claims to the garbage collector that a device address, or a host buffer
the library reads after the call returns, is a live Go pointer. They are
distinct types so the compiler refuses to swap them.

A nil error from `Getrf` or `Getrs` means the work was enqueued. `dInfo` is a
single int in device memory and is what says whether it succeeded; read it back
after synchronizing the stream.

## Early access

`MatrixScatterH2D` and `MatrixGatherD2H` are marked in NVIDIA's header as
shipped for early access and not part of the official release. They are bound
because the physical test needs them to get a matrix in and an answer out.
