# lldb

Status: experimental. This package exposes raw, generated SB API bindings. It
has no repository consumer, and its bridge has not been validated against a
retained LLDB installation receipt. Callers should use `Load` and `Require`
before creating handles and must follow the explicit ownership rules below.

This directory is generated by `gen-lldb`. The Go bindings load a
C++ bridge, not liblldb itself: liblldb exposes a C++ ABI and its symbols
cannot safely be called directly from Go.

Compile `bridge/lldb_bridge.cc` with the headers and liblldb from the
same LLVM installation. On macOS, for example:

```sh
clang++ -std=c++17 -fPIC -dynamiclib bridge/lldb_bridge.cc \
  -I"$LLVM_PREFIX/include" -L"$LLVM_PREFIX/lib" -llldb \
  -Wl,-rpath,"$LLVM_PREFIX/lib" -o liblldb_bridge.dylib
```

Set `LIBLLDB_BRIDGE_PATH` to the resulting shared library before using
the package, or call `Load` with that path. The bridge and liblldb must
come from one LLVM installation. Call `LLDBSBDebuggerDestroy` before
deleting a debugger created with `LLDBSBDebuggerCreateWithInitFiles`.

To verify generated files and the bridge receipt have not drifted, run:

```sh
gen-lldb -check -output lldb -bridge-output lldb/bridge
```
